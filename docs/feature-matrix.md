# Palwyn — Feature Matrix

Feasibility column from [phase-0-feasibility.md](phase-0-feasibility.md). Palwyn is free and will be open source; there are no paid plans.

| Feature | Release | Feasibility | Android permission(s) |
|---|---|---|---|
| Tray presence, status, quick actions | MVP | Supported | — |
| Pairing + secure link | MVP | Supported | Nearby devices (API 37+), `POST_NOTIFICATIONS` |
| Device info, battery, storage | MVP | Supported | — |
| Incoming call alert + caller ID | MVP | **Built (Phase 6)**, verified on device: card on PC within ~0.1 s of ringing (screen on); name from contacts | `READ_PHONE_STATE`, `READ_CALL_LOG`, `READ_CONTACTS` |
| Answer / decline / end from PC | MVP | **Built (Phase 6)**: answer, decline and end verified on device (0.2 s). Deprecated API, no mute/hold (Phase 0 §2) | `ANSWER_PHONE_CALLS` |
| Call audio on PC (Bluetooth HFP) | — | **Not practical** — Windows denies the API to non-Microsoft apps (Phase 0 §7) | — |
| Call history | MVP | **Built (Phase 6)**: read live from the phone's call log, nothing stored on the PC. Play needs a permission declaration | `READ_CALL_LOG` |
| SMS read, receive, send | MVP | **Built (Phase 7)**, verified on device: conversations, new-message notifications with reply, replies from the PC, emoji; new messages to any number or contact (batch 2). No RCS. Play needs a permission declaration | `READ_SMS`, `SEND_SMS` |
| SMS search, multi-device threads | V1 | Supported | same |
| MMS | V1 | **Built (batch 2)**, verified on device by the user (2026-09-29): pictures and group messages in conversations with sender names, pictures shown inline, other attachments open on click; group replies go as one text-only MMS to everyone (carrier MMS rate, needs mobile data). Sending pictures from the PC: not built. An MMS the SMS app hasn't downloaded yet isn't listed | same |
| RCS | — | Restricted — notification reply only | — |
| Notification mirroring + dismiss | MVP | **Built (Phase 8)**, verified on device: live list with app icons, Windows notifications, dismiss syncs to the phone | Notification access |
| Notification actions / quick reply | MVP | **Built (Phase 8)**, verified on device (WhatsApp/Messenger reply from the page and from Windows notifications). Actions that open a phone screen may be blocked by Android | Notification access |
| Per-app filters, history, search | V1 | Per-app on/off **built (Phase 8)**. History and search **built (batch 3)**, verified with a test notification: the last 500 per phone on the PC (JSON in the app's LocalState), reposts with the same words skipped, searchable by app, title and text; on by default, turning it off deletes it | Notification access |
| PC notifications on the phone | V1 | **Built (batch 3)**, verified on device by the user (2026-09-29): new Windows notifications (via UserNotificationListener, Windows asks once) appear on the phone while connected and go when dismissed on the PC; ones already there when it starts are not sent; Palwyn's own are never sent. Polled every 2 s (the change event isn't available to desktop apps). Off by default. Text only, no actions from the phone | Android notifications allowed |
| Recent photos and videos, download to PC | MVP | **Built (Phases 9–10)**, verified on device: previews, open full size, save to Pictures (≈ 20 MB/s on the test Wi-Fi); videos with duration badge | `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO` |
| Albums, full gallery, batch transfer | V1 | **Built (batch 4)**, verified on device: album picker (MediaStore buckets with counts) filters the Photos page; "Select all" then "Save to Pictures" copies a batch (the gallery pages in 100 at a time with "Show older") | same |
| PC → phone upload | V1 | **Built (Phase 10)** as Quick Drop: any file to Download/Palwyn, verified on device | — |
| Storage explorer | V1 | Partial (Play policy) | All-files access |
| Quick Drop (files, text, links) | V1 | **Built (Phase 10)**, verified on device both ways: Send to phone window, Windows Share target, Android "Send to PC" share. Folders (batch 4, verified on device by the user (2026-09-29)): drop or choose a folder and everything in it (up to 1,000 files) keeps its folders under Download/Palwyn; one notification per folder | — |
| Clipboard PC → phone | V1 | **Built (Phase 11)**, verified on device: automatic for every text copy while the PC setting is on (off by default; quick switch in the tray); password-manager copies skipped. Images too (batch 4, verified on device by the user (2026-09-29)): PNG up to 20 MB, put on the phone's clipboard as an image | — |
| Clipboard phone → PC | V1 | **Built (Phase 11)**, verified on device, but **restricted by Android 10+**: never automatic. "Send to PC" on selected text, or "Send clipboard to PC" (Quick Settings tile, notification, app); sensitive clips refused. A copied image goes too (batch 4, verified on device by the user (2026-09-29)) | — |
| Links both ways ("deep links") | V1 | **Built (Phases 10–11)** through Quick Drop and the clipboard: a link opens from the notification on the other side | — |
| Media controls | V1 | **Built (Phase 12)**: now playing, play/pause, next, previous, phone volume, in the tray and on Home | Notification access |
| Contacts | V1 | **Built**: browse and search the phone's contacts on the PC; add, edit and delete them (saved on the phone); add or edit a caller/sender from Calls and Messages. New contacts go to phone storage, not a Google account. Contact pictures show on the PC (batch 2), but can't be changed there | `READ_CONTACTS`, `WRITE_CONTACTS` |
| Search calls and messages | V1 | **Built**: by name or number, and message text; runs on the phone | `READ_CALL_LOG`, `READ_SMS` |
| Pause PC media during calls | V1 | **Built (batch 1)**: players in Windows' media controls pause when the phone rings and resume after (only those Palwyn paused, only if still paused); a dropped link counts as the call ending. On by default | — |
| Keep PC awake while connected | V1 | **Built (batch 1)**: one Windows power request (display + system) while the phone is connected: no sleep, screen-off, screensaver or idle lock; shown in `powercfg /requests`. Off by default | — |
| Take a photo from the PC | V1 | **Built (batch 4)**: the request and the phone notification verified on device; taking and receiving the photo verified on device by the user (2026-09-29). Camera button on the Photos page; tapping the phone notification opens its camera app; the photo is saved to the PC's photos folder, not the phone gallery. No live preview or webcam | — (no camera permission: uses the camera app) |
| Ring my phone | V1 | **Built (Phase 12)**: ringtone at full alarm volume, even in silent mode; Do Not Disturb can still silence it (no DND access requested) | — |
| Phone dashboard | V1 | **Built (Phase 12)**: battery, Wi-Fi signal (not the network name: needs location), Bluetooth on/off, mobile signal, network type and carrier (batch 6), storage, model, Android version, connection, recent activity | — |
| Quick Actions | V1 | **Built (Phase 12)**: ring, send clipboard, send files, latest photo. Opening a phone app/screen from the PC: **restricted** (Android background activity starts) | — |
| Multiple phones | V1 | **Built (batch 6)**, one connected at a time: pair several, pick the one in use in Settings, remove any; notification history, contact pictures and photo previews are kept per phone. Switching verified on device by the user (2026-09-29). Several phones connected at once: not built (every page assumes one link) | — |
| USB cable | V1 | **Built (2026-09-29)**, verified on device by the user: switches to the cable when plugged in and back to Wi-Fi when unplugged, while running (log: about 1 s each way). With USB debugging on, the PC finds the plugged-in phone through adb and forwards a local port (47801) to the phone's link port; the same pinned TLS link then runs over the cable, checked against the paired phone before switching, and goes back to Wi-Fi when unplugged. Home says "Live over the USB cable". Needs adb on the PC (Android SDK Platform Tools, free, not bundled) and the phone's one-time "Allow USB debugging?" answer. Checked only when a USB device comes or goes. Pairing still needs one network. Without USB debugging (USB tethering, accessory mode): not built | — (Developer options > USB debugging) |
| Connect by address (VPN, other networks) | V1 | **Built (batch 6)**, verified on device with the phone's LAN IP: set an IP or host (Tailscale, ZeroTier, a network that blocks discovery) per phone in Settings; the PC then connects only there, still pinned TLS. Pairing still needs both on one network. Bluetooth link: **not built** (a second transport on both sides; KDE Connect's is experimental too) | — |
| Phone as touchpad and keyboard | V1 | **Built (batch 5)**: pointer movement and tap-to-click verified on device; typing, two-finger right-click and scroll, and hold-to-drag verified on device by the user (2026-09-29). Remote > Touchpad on the phone: move, tap, two-finger tap (right-click), two-finger scroll, hold then move (drag); arrow/Esc/Tab/Backspace/Enter keys; live typing, any language (Unicode). Needs "Mouse and keyboard" on the PC (off by default). Can't reach the Windows sign-in screen, UAC prompts, or apps running with higher rights than Palwyn | — |
| Presentation remote | V1 | **Built (batch 5)**, verified on device by the user (2026-09-29): Remote > Slides: big Next/Previous (arrow keys), Start slideshow (F5), End (Esc); the phone's volume keys also change slides and the screen stays on | — |
| PC media, volume and lock from the phone | V1 | **Built (batch 5)**, verified on device by the user (2026-09-29): Remote > PC shows what's playing on the PC (Windows media controls), play/pause/next/previous, the speakers' volume and mute (Core Audio), and Lock PC. "Music, volume and lock" on the PC, on by default | — |
| Run PC commands from the phone | V1 | **Built (batch 5)**, verified on device by the user (2026-09-29): commands added in the PC's Settings (name + Command Prompt line) appear as buttons on the phone, which sees only their names. They run as the PC's user, without a window | — |
| Themes / customization | V1 | **Built**: light, dark or Windows setting, window transparency (tray and Settings). Redesign (2026-09-29): Home is a tile dashboard on both apps, JetBrains Mono (SIL OFL, bundled) is the app font with the system font kept for message and notification text on Windows, and the brand green is the accent on both (Android no longer takes wallpaper colours). Both verified on device (Windows Home, narrow layout, light and dark; Android Home and the Slides tile). Lock PC from the new tile uses the existing lock request, not re-tested | — |
| Phone screen on the PC | V2 | **Built (batch 8)**: viewing verified on device (the phone's screen live in the PC window, stops on both sides when the window closes); control verified on device by the user (2026-09-29). "Phone screen" in the tray and on Home: the phone shows a notification, then Android's consent dialog (every time). "Keep screen sharing ready" on the phone (off by default, 2026-09-29): Android asks once, then the PC can reopen it without touching the phone until Stop or a phone restart; built, first real run pending. JPEG frames, up to 1280 px, only on change. Control, if allowed on the phone: click = tap, drag = straight swipe (sent on release), wheel = swipe, right-click/Esc = Back, Home and Recents buttons, typing fills the focused field. Secure windows (banking, DRM video) stay black; no sound; the phone must stay unlocked. H.264 for smoother video: later | — (consent each time); control: accessibility service |
